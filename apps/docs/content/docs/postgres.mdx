---
title: PostgreSQL storage
description: The only implemented production storage adapter.
---

<code>@egy-pay/storage-postgres</code> implements the core’s transactional storage port using node-postgres. PostgreSQL is the only production adapter included today.

## Create the adapter

~~~ts
import { Pool } from 'pg';
import { PostgresPaymentStore, migratePostgres } from '@egy-pay/storage-postgres';

const pool = new Pool({ connectionString: process.env.DATABASE_URL });
const storage = new PostgresPaymentStore(pool);

await migratePostgres(pool);
~~~

Create one pool per process, share the adapter with the service, and close the pool during shutdown. Prefer running migrations as a deployment step rather than on every web request.

## Atomic writes

A payment command uses one PostgreSQL transaction for the related state update, claim or verification record, idempotency result, and outbox event. The adapter uses version checks and database constraints to handle concurrent requests and uniqueness.

The integration tests run against a real PostgreSQL server. Use a dedicated test database; the tests create and remove their own isolated schema.

## Other databases

The core owns a transactional storage port, so other adapters can be added later. MySQL and MongoDB adapters do not exist today. Any future adapter must preserve the atomic transaction, concurrency, uniqueness, idempotency, audit, and outbox guarantees rather than offering a weaker best-effort implementation.
